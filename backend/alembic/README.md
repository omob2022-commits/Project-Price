# Database Migrations with Alembic

This directory contains Alembic migrations for the Palestine Land Valuation platform.

## Overview

The migration system is configured to work with:
- **PostgreSQL** with **PostGIS** extension
- **Async SQLAlchemy** (asyncpg driver)
- **GeoAlchemy2** for spatial types

## Migration Files

Migrations are timestamped and run in order:

1. **20260808_0000_init_postgis.py** - Enables PostGIS extension (MUST run first)
2. **20260808_0001_create_initial_schema.py** - Creates all tables with GiST spatial indexes

## Usage

### Quick Start

```bash
# From backend directory
./scripts/migrate.sh upgrade
```

### Available Commands

```bash
# Apply all pending migrations
./scripts/migrate.sh upgrade

# Rollback one migration
./scripts/migrate.sh downgrade

# Show current database revision
./scripts/migrate.sh current

# View migration history
./scripts/migrate.sh history

# Create a new migration (autogenerate from models)
./scripts/migrate.sh create "add_new_column"
```

### Manual Alembic Commands

```bash
# Apply all migrations
python -m alembic upgrade head

# Rollback to specific revision
python -m alembic downgrade <revision>

# Show current revision
python -m alembic current

# Generate migration from model changes
python -m alembic revision --autogenerate -m "description"

# View migration SQL without applying
python -m alembic upgrade head --sql
```

## Environment Setup

Alembic reads database configuration from `app.core.config.Settings`, which loads from:
1. Environment variables
2. `.env` file in backend directory

Required environment variables:
```bash
DATABASE_URL_SYNC=postgresql://landval:password@localhost:5432/landval_db
```

## PostGIS Requirement

The database **must** have the PostGIS extension enabled before running migrations. The first migration (`20260808_0000`) handles this, but requires database superuser privileges.

If you don't have superuser access, ask your DBA to run:
```sql
CREATE EXTENSION IF NOT EXISTS postgis;
```

## Creating New Migrations

### Autogenerate (Recommended)

After modifying models in `app/models/`:

```bash
./scripts/migrate.sh create "add_field_to_parcel"
```

Alembic will:
1. Compare current models to database schema
2. Generate migration code automatically
3. Create a new file in `versions/`

**Always review autogenerated migrations before applying!**

### Manual Migration

For complex changes (raw SQL, PostGIS functions, etc.):

```bash
python -m alembic revision -m "add_spatial_function"
```

Then edit the generated file in `versions/` directory.

## GiST Spatial Indexes

All geometry columns have GiST indexes for efficient spatial queries:
- `ST_Intersects` (point-in-polygon)
- `ST_DWithin` (distance queries)
- `ST_Distance` (nearest neighbor)

These indexes are created via raw SQL in migrations:
```sql
CREATE INDEX idx_name ON table_name USING GIST (geometry);
```

## Data Provenance

Per blueprint directive, all spatial data tables include:
- `source_version`: Dataset version identifier
- `effective_date`: When the data became effective

This prevents financial miscalculations from stale geopolitical boundaries.

## Troubleshooting

### PostGIS Not Found

**Error:** `ERROR: type "geometry" does not exist`

**Solution:** Run the PostGIS initialization migration:
```bash
python -m alembic upgrade 20260808_0000
```

### Permission Denied for PostGIS

**Error:** `ERROR: permission denied to create extension "postgis"`

**Solution:** Ask your DBA to enable PostGIS, or connect as superuser:
```sql
psql -U postgres -d landval_db -c "CREATE EXTENSION postgis;"
```

### Autogenerate Not Detecting Changes

**Error:** Alembic doesn't see your model changes

**Solutions:**
1. Ensure models are imported in `alembic/env.py`
2. Check that `target_metadata = Base.metadata` is set
3. Verify models inherit from correct `Base` class
4. Try with `--autogenerate` flag explicitly

### Migration Conflict

**Error:** `Can't locate revision identified by 'xyz'`

**Solution:** Check migration order and dependencies:
```bash
python -m alembic history
python -m alembic branches
```

## Best Practices

1. **Always backup** production data before migrations
2. **Test migrations** on staging environment first
3. **Review autogenerated** migrations before applying
4. **Never edit** applied migrations - create new ones instead
5. **Use transactions** - Alembic wraps migrations in transactions by default
6. **Document complex** migrations with comments
7. **Track data lineage** - update `spatial_data_changelog` for ETL imports

## Phase 1 Scope

Current migrations are scoped to **Nablus Governorate** only. The schema is designed for expansion to all of Palestine, but Phase 1 data imports are Nablus-specific.

See ETL documentation for data import procedures.
